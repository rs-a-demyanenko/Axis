# Руководство Axis

[← Главная](../README.md)

Команды сборки и пути в примерах ниже указаны относительно корня репозитория.

Библиотека Arduino для управления одной осью станка с коллекторным двигателем и обратной связью по энкодеру. Поддерживает линейные и вращательные оси, движение к точке, регулирование скорости, homing, физические и программные ограничения.

Axis защищённо наследуется от [GyverMotor2](https://github.com/GyverLibs/GyverMotor2). Эта зависимость формирует сигналы драйвера; Axis добавляет профиль движения, регуляторы, координаты и обработку ошибок. Внутри Axis нет динамического выделения памяти, `String`, `delay()` или ожидания завершения движения. Ненулевой `setDeadtime()` добавляет короткую задержку при реверсе в самой GyverMotor2.

Версия: **0.1.0**. Исходный проектный документ: [AXIS_PLAN.md](../AXIS_PLAN.md).

## Возможности

- Каскад: P-регулятор позиции → PID-регулятор скорости → ШИМ. По умолчанию скоростной контур работает как PI: `velocityKd = 0`.
- Трапецеидальный профиль скорости; на коротком перемещении — треугольный. Раздельные ускорение и замедление.
- Абсолютные команды после homing и ограниченные относительные команды до него.
- Машинная и рабочая системы координат.
- Линейные и вращательные энкодеры с настраиваемым масштабом; программный квадратурный декодер ×4 либо внешний счётчик.
- Ограниченные и непрерывные вращательные оси, выбор направления движения к углу.
- MIN/MAX/Home, совмещённый Home/концевик, ограниченный отход от концевика.
- Неблокирующий homing с повторным медленным подходом и парковкой.
- Удержание позиции или отключение после достижения цели.
- Зафиксированные ошибки, контроль слежения, возможного заклинивания, периода управления и правдоподобия счётчика.
- Ядро `axis::Core`, не зависящее от Arduino, и тесты на моделируемом двигателе.

## Платформы и драйверы

Код использует C++11 и стандартные функции Arduino. Архитектура библиотеки не привязана к конкретной плате; ESP32 поддерживается, включая чтение энкодера с защитой от одновременного доступа двух ядер. Частота контура и максимальная частота энкодера зависят от процессора и приложения. Сборка конкретной платы и работа на реальном станке — разные виды проверки.

Объявление объекта сохраняет параметры шаблона GyverMotor2:

```cpp
Axis<GM2::DIR_PWM> x(4, 5);            // DIR, PWM
Axis<GM2::DIR_PWM_INV> y(6, 9);        // DIR, инверсный PWM
Axis<GM2::PWM_PWM_SPEED> a(10, 11);    // PWM, PWM
Axis<GM2::PWM_PWM_POWER> b(10, 11);    // PWM, PWM
Axis<GM2::DIR_DIR_PWM> z(4, 7, 5);     // DIR, DIR, PWM
```

Выбирайте режим по таблице сигналов **своего драйвера** в документации GyverMotor2. Тип `DIR_PWM` не является универсальным обозначением любого H-моста.

`GM2::ONLY_PWM` и `GM2::DIR_DIR` компилируются как параметры шаблона, но `begin()` возвращает `UNSUPPORTED`: для этого контроллера требуется двунаправленный регулируемый выход.

По умолчанию разрешение ШИМ — 8 бит. `Axis<GM2::DIR_PWM, 10>` меняет диапазон выходных значений, но **не настраивает аппаратное разрешение ШИМ**. Его необходимо отдельно настроить средствами выбранной платы. Для обычного Uno оставляйте 8 бит. Для ESP32 используется совместимый с GyverMotor2 вызов `analogWrite()`; прямого вызова удалённых в новых ядрах LEDC API в Axis нет.

Унаследованные `runSpeed()`, `setAccel()` и `setMinDuty()` не открыты наружу: они могли бы обойти контуры и ограничения. Ускорение GyverMotor2 и её минимальный ШИМ принудительно установлены в ноль. Выход регулятора имеет линейный диапазон вокруг нуля.

## Установка

1. Установите **GyverMotor2** через менеджер библиотек Arduino IDE либо из её репозитория.
2. Поместите каталог Axis в каталог пользовательских библиотек Arduino, например `Documents/Arduino/libraries/Axis`, либо установите ZIP библиотеки.
3. Откройте пример через **Файл → Примеры → Axis** и настройте пины, масштаб и механику.

Для PlatformIO можно поместить репозиторий в `lib/Axis` своего проекта или добавить Git-зависимость:

```ini
lib_deps =
    https://github.com/rs-a-demyanenko/Axis.git
```

Метаданные зависимости GyverMotor2 включены в `library.properties` и `library.json`. Для воспроизводимой сборки своего проекта зафиксируйте проверенные ревизии зависимостей.

## Быстрый старт

Полные примеры содержат регистрацию прерываний и атомарное чтение счётчика. Основная последовательность:

```cpp
#include <Axis.h>

Axis<GM2::DIR_PWM> machineAxis(4, 5);

// Реализуйте чтение настоящего счётчика энкодера с защитой от ISR.
uint32_t readEncoder(void* context);

void setup() {
    // Перед этим настройте энкодер и его прерывания.
    machineAxis.attachEncoder(readEncoder);

    axis::Pins pins;
    pins.minLimit = axis::InputPin(8);
    pins.maxLimit = axis::InputPin(9);
    pins.home = axis::InputPin(10);
    machineAxis.setPins(pins);

    axis::Config config;
    config.encoder = axis::EncoderScale::rotary(2000, 5);
    config.maxSpeed = 10;                 // мм/с
    config.acceleration = 30;             // мм/с²
    config.deceleration = 30;
    config.softMin = 0;
    config.softMax = 100;
    config.home.switchPosition = -1;
    config.home.parkPosition = 0;

    axis::Result result = machineAxis.begin(config);
    // Обработайте result. Сам begin() не запускает мотор.
}

void loop() {
    machineAxis.tick();
    // По команде оператора: machineAxis.home();
    // После успешного home: machineAxis.moveTo(20, 5);
    // Не вызывайте команды повторно на каждом проходе loop().
}
```

В примерах движение начинается только по команде из Serial. Начальные коэффициенты регуляторов приведены для знакомства с API: они не являются готовой настройкой для любого двигателя.

## Как работает управление

```text
moveTo / moveBy → профиль позиции и скорости
                           ↓
              v_cmd = v_ref + Kp_pos × (p_ref − p)
                           ↓
                     ограничение скорости
                           ↓
                   скоростной PID → ШИМ
                           ↓
                   GyverMotor2 → двигатель
                           ↓
                   энкодер → позиция и скорость
```

`p_ref` — текущая позиция профиля, а не сразу конечная цель. Профиль разгоняет ось, поддерживает скорость и тормозит. Для короткого пути максимальная скорость уменьшается так, чтобы осталось место на торможение.

Скоростной контур:

```text
e_v = v_cmd − v_measured
u = Kp_v × e_v + integral − Kd_v × derivative(v_measured) + Kff × v_cmd
```

`u` нормирован к диапазону `[-1; +1]`, ограничивается `maxOutput`, затем переводится в целочисленный ШИМ. На границе насыщения интегратор не накапливает ошибку в сторону дальнейшего насыщения; обратное накопление, уменьшающее насыщение, разрешено. Производная берётся по измерению, чтобы изменение задания не создавало производного скачка. Для скорости и производной предусмотрены фильтры первого порядка.

Это не контур тока или момента. Параметры ускорения задают профиль; реальная механика может отставать, колебаться или превышать заданную скорость при неправильной настройке. Пределы необходимо согласовать с возможностями двигателя, питания, драйвера и нагрузки.

## Масштаб энкодера и единицы

Тип оси (`Kind`) и тип энкодера (`EncoderScale`) независимы.

| Ось | Координата | Скорость | Ускорение |
|---|---|---|---|
| `Kind::LINEAR` | мм | мм/с | мм/с² |
| `Kind::ROTARY` | градусы | °/с | °/с² |

Используйте **отсчёты после декодирования**, а не паспортные PPR без уточнения режима. При декодировании ×4 энкодер 500 PPR обычно даёт 2000 отсчётов за оборот, если производитель определяет PPR как периоды одного канала. Проверьте определение своего энкодера.

```cpp
config.encoder = axis::EncoderScale::linear(100);       // 100 отсчётов/мм
config.encoder = axis::EncoderScale::rotary(2000, 5);    // 2000 отсчётов на 5 мм
config.encoder = axis::EncoderScale::rotary(1440);       // 1440 отсчётов на 360°
config.encoder.inverted = true;                         // инверсия измерения
```

Для вращательного энкодера:

```text
countsPerUnit = countsPerEncoderRevolution / axisUnitsPerEncoderRevolution
```

Если энкодер установлен на двигателе, редуктор имеет отношение `G = обороты двигателя / обороты выхода`, а винт перемещает каретку на `L` мм за оборот выхода, передайте `unitsPerRevolution = L / G`. Для вращательной оси — `360 / G`.

`positionTolerance` должен составлять не менее одного отсчёта: `positionTolerance × countsPerUnit >= 1`. `begin()` проверяет это условие. Разрешение измерения не равно точности всей оси: люфт, упругость и проскальзывание передачи остаются свойствами механики.

Входной счётчик — `uint32_t` с переполнением по модулю 2³². Знаковый 32-битный аппаратный счётчик можно преобразовать к `uint32_t`. Между соседними чтениями модуль приращения должен быть меньше 2³¹. Ядро накапливает отсчёты в `int64_t`; `getCounts()` возвращает накопленное приращение с момента `begin()`, до применения инверсии и масштаба. `begin()` принимает исходное значение счётчика за начальную точку измерения, не обнуляя сам аппаратный счётчик.

Позиция и регуляторы используют `double`; на AVR он обычно имеет точность `float`. При очень больших накопленных координатах дробная точность уменьшается. `getAngle()` нормализует представление угла, но не устраняет ограничение точности длинного многооборотного движения. Для таких применений потребуется периодическое управляемое переопределение координат или расширение представления координат.

### Квадратурный декодер

`axis::Quadrature` декодирует A/B в режиме ×4. Вызывайте `update(a, b)` на `CHANGE` **обоих** каналов. Последовательность `00 → 10 → 11 → 01 → 00` увеличивает счётчик на четыре. Переход сразу по двум битам считается недопустимым: отсчёт не меняется, растёт `invalidTransitionsUnsafe()`.

Объект декодера не регистрирует прерывания и не управляет глобальной маской прерываний. `readUnsafe()` требует внешней защиты:

- AVR: `ATOMIC_BLOCK(ATOMIC_RESTORESTATE)` сохраняет прежнее состояние прерываний.
- ESP32: один и тот же `portMUX_TYPE` в ISR и функции чтения. Одного `noInterrupts()` недостаточно для защиты от другого ядра.
- Другие Arduino-платформы: используйте их механизм атомарного снимка или аппаратный счётчик.

Для высокой частоты импульсов предпочтителен аппаратный счётчик. Автоматическое подключение ESP32 PCNT в этой версии не реализовано, но его можно подключить через `attachEncoder()`.

## Машинные и рабочие координаты

После `begin()` привязки нет. `moveTo()` и непрерывный `jog()` возвращают `NOT_HOMED`. До homing можно выполнить `moveBy()`, если разрешён `allowUnhomedRelative`: длина ограничена `unhomedMaxDistance`, скорость дополнительно ограничивается `unhomedMaxSpeed`. Ограничение длины действует **на каждую команду**, а не определяет неизвестное расстояние до физического края. Программные машинные границы до привязки недостоверны.

После успешного `home()` абсолютное движение разрешено из любой позиции, пока привязка достоверна.

```cpp
machineAxis.moveTo(25, 5);                      // машинная координата 25
machineAxis.moveBy(-3, 2);                      // от фактической текущей позиции
machineAxis.setWorkPosition(0);                // текущая точка — рабочий ноль
machineAxis.moveTo(10, 2, axis::Frame::WORK);    // рабочая координата 10
```

Рабочее смещение не меняет счётчик, машинную привязку и программные границы. Повторный homing сбрасывает рабочее смещение.

`disable()` сохраняет привязку, если счётчик продолжает достоверно отслеживать движение. Если это условие нарушено, вызовите `invalidateReference()`. Перезапуск, повторный `begin()`, изменение подключения энкодера, `setMotorReverse()` и ошибки потери измерения требуют повторного homing.

## Homing

Настройка отдельного датчика:

```cpp
config.home.source = axis::HomeSource::SEPARATE;
config.home.direction = -1;
config.home.searchSpeed = 2;
config.home.latchSpeed = 0.5;
config.home.backoff = 1;
config.home.switchPosition = -1;
config.home.parkPosition = 0;
config.home.maxTravel = 120;
config.home.timeoutUs = 90000000;
```

Последовательность:

1. Если Home уже активен, ось медленно освобождает его и останавливается.
2. Движется к Home со скоростью `searchSpeed`.
3. После подтверждённого срабатывания тормозит.
4. Отходит в обратную сторону не менее чем на `backoff`, освобождает датчик и останавливается.
5. Повторно подходит со скоростью `latchSpeed`.
6. Сохраняет счётчик первого сырого фронта принятого устойчивого срабатывания и присваивает этой точке `switchPosition`.
7. Тормозит и выполняет профиль до `parkPosition`.
8. После достижения допусков и выдержки `settleTimeUs` устанавливает `isHomed() = true`.

`switchPosition` и `parkPosition` — разные координаты. Например, датчик находится в −1 мм, а парковка — в 0 мм. Счётчик сырого фронта устраняет смещение, создаваемое самим ожиданием debounce и последующим торможением; точность всё равно ограничена периодом опроса и датчиком.

Для общего MIN/Home:

```cpp
config.home.source = axis::HomeSource::MIN_LIMIT;
config.home.direction = -1;
```

В этом случае используется вход MIN; отдельный `pins.home` не нужен. Для MAX/Home задайте `MAX_LIMIT` и направление `+1`. Парковка должна находиться в стороне освобождения общего концевика. Исключение для общего концевика действует только в homing; противоположный концевик продолжает останавливать ось.

На время homing обычные программные границы отключены: координата ещё определяется, а датчик может находиться вне рабочего диапазона. Конечная парковочная точка проверяется по настроенным границам. Поиск, все отходы и парковка вместе ограничены `maxTravel` по **суммарному пройденному пути** и `timeoutUs`.

`stop()` прерывает homing с торможением; прерванный homing не создаёт достоверной привязки. `disable()`, `brake()` и авария также отменяют его. Индекс Z энкодера и автоматическая привязка по абсолютному датчику пока не реализованы.

## Физические входы и ограничения

```cpp
axis::Pins pins;
pins.minLimit = axis::InputPin(8);                // LOW активен, INPUT_PULLUP
pins.maxLimit = axis::InputPin(9, false, false);  // HIGH активен, INPUT
pins.home = axis::InputPin(10);
pins.emergency = axis::InputPin(11);
machineAxis.setPins(pins);
```

Неназначенный вход имеет номер `0xff` и считается неактивным. В примерах использовано замыкание входа на GND при срабатывании. Для NC-цепи, оптического датчика или внешней подтяжки выберите соответствующую полярность и обвязку.

MIN/MAX срабатывают по сырому сигналу сразу, при очередном `tick()`, без ожидания периода регулятора. Освобождение подтверждается в течение `limitReleaseUs`. Home использует устойчивое состояние в течение `home.debounceUs`.

В обычном движении и при удержании активный концевик фиксирует ошибку и выполняет `faultAction`. Два активных концевика дают `BOTH_LIMITS`, в том числе в покое. После одиночного срабатывания можно явно заказать ограниченный отход:

```cpp
machineAxis.recoverFromLimit(+1, 2);  // от MIN на 2 единицы
machineAxis.recoverFromLimit(-1, 2);  // от MAX на 2 единицы
```

Отход разрешён только от соответствующего активного концевика, с исправным энкодером и без другой аварии. Перед началом измеренная скорость должна уменьшиться до допуска. Ограничены расстояние и скорость. Пока концевик активен, выход в его сторону блокируется. После освобождения разрешено обратное управляющее воздействие для торможения и коррекции перелёта. Если в конце отхода концевик остаётся активным, снова фиксируется ошибка. Для привязанной оси также нельзя пересечь противоположную программную границу. Если конечная точка всё ещё вне рабочего диапазона, дальнейшее обычное управление вызовет `SOFT_LIMIT`; выбирайте достаточную длину отхода.

Программные границы относятся к машинной координате. Проверяются цель команды и фактическое положение. Скорость в сторону границы дополнительно ограничивается по оставшемуся расстоянию, `deceleration` и запасу на `maxTickGapUs`. Поэтому `jog()` замедляется у границы и завершается как `STOPPED`. У `moveTo()` цель не обрезается молча: команда вне диапазона возвращает `OUT_OF_RANGE`.

Эта логика предполагает, что настроенное замедление достижимо. Концевики, механические упоры, силовой драйвер и аппаратный аварийный останов должны соответствовать реальному тормозному пути. Программный аварийный вход не заменяет независимое отключение опасного движения.

## Вращательная ось

```cpp
config.kind = axis::Kind::ROTARY;
config.encoder = axis::EncoderScale::rotary(1440);
config.continuous = true;
config.softLimitsEnabled = false;  // только если механика допускает любые обороты
```

`getPosition()` возвращает накопленную координату, например 730°. `getAngle()` — её представление по модулю `rotaryPeriod`, по умолчанию `[0; 360)`.

```cpp
machineAxis.moveToAngle(10);                            // кратчайший путь
machineAxis.moveToAngle(10, axis::Direction::POSITIVE);
machineAxis.moveToAngle(10, axis::Direction::NEGATIVE);
machineAxis.moveBy(720, 60);                            // именно два оборота
machineAxis.moveTo(730, 60);                            // накопленная машинная цель
```

Переход 350° → 10° по кратчайшему пути задаёт +20°. При точном равенстве двух путей выбирается положительное направление. Для совпадающих углов путь равен нулю; полный оборот задавайте через `moveBy()`.

Для ограниченной поворотной оси оставьте `continuous = false` и задайте `softMin`/`softMax`, например −90…+90°. Здесь используются `moveTo()` и `moveBy()`, а `moveToAngle()` возвращает `UNSUPPORTED`.

У непрерывной оси также можно включить границы накопленной координаты, например для защиты кабеля. Если выбранный путь выходит за них, команда отклоняется; другой путь автоматически не подбирается. Несколько раздельных запрещённых угловых секторов эта версия не поддерживает.

## Остановка, завершение и удержание

| Метод / настройка | Поведение |
|---|---|
| `stop()` | Отменяет прежнюю цель, тормозит по `deceleration`, затем удерживает фактическую точку или отключает выход согласно `endAction` |
| `disable()` | Немедленно переводит выход в режим отключения GyverMotor2, отменяет движение |
| `brake()` | Немедленно включает торможение средствами GyverMotor2, отменяет движение |
| `emergencyStop()` | Фиксирует `EMERGENCY_STOP`, сбрасывает привязку, выполняет `faultAction` |
| `EndAction::HOLD` | После завершения продолжает регулирование позиции |
| `EndAction::COAST` | После завершения отключает выход |
| `FaultAction::COAST` | При аварии отключает выход; значение по умолчанию |
| `FaultAction::BRAKE` | При аварии включает торможение средствами драйвера |

«Немедленно» относится к переключению выхода при вызове метода, а не к мгновенной остановке механики. Торможение драйвером зависит от его схемы. Для вертикальной оси отключение или электрическое торможение могут быть недостаточны — отдельный механический тормоз этой библиотекой автоматически не управляется.

`Result::OK` означает **принятие** команды. `isBusy()` показывает выполнение движения или homing. В состоянии удержания он уже `false`, хотя регулятор продолжает работать.

Цель достигнута после окончания профиля, когда ошибка позиции не превышает `positionTolerance`, а скорость — `velocityTolerance`, непрерывно в течение `settleTimeUs`. `inPosition()` отражает этот статус. Выход из него использует дополнительный `positionHysteresis`; это гистерезис статуса, а не зона отключения регулятора.

Результат выполнения доступен через `getCompletion()`:

- `NONE` — движения ещё не было.
- `RUNNING` — команда выполняется.
- `REACHED` — цель достигнута, включая успешный homing.
- `STOPPED` — выполнена плавная остановка.
- `CANCELLED` — движение отменено отключением или торможением.
- `FAULTED` — выполнение прервано аварией.

Новые команды во время движения отклоняются с `BUSY`. Также требуется малая измеренная скорость перед началом нового движения. Очередь команд и смена цели на ходу пока отсутствуют.

## Настройки `axis::Config`

Параметры времени с суффиксом `Us` задаются в **микросекундах**, постоянные фильтров — в **секундах**. Ненулевые интервалы должны быть меньше 2³¹ мкс. Нулевой debounce допустим.

| Поле | По умолчанию | Назначение |
|---|---:|---|
| `kind`, `continuous`, `rotaryPeriod` | LINEAR, false, 360 | Геометрия оси |
| `encoder.countsPerUnit` | 100 | Масштаб измерения |
| `encoder.inverted` | false | Инверсия направления измерения |
| `maxSpeed` | 20 | Верхний предел задания скорости |
| `acceleration`, `deceleration` | 100, 100 | Параметры профиля |
| `positionKp` | 8 | Коэффициент внешнего контура, 1/с |
| `velocityKp`, `velocityKi`, `velocityKd` | 0.08, 0.4, 0 | Скоростной PID в нормированных единицах выхода |
| `velocityFeedforward` | 0 | Добавка выхода пропорционально заданной скорости |
| `velocityFilterTime` | 0.02 | Фильтр измеренной скорости; 0 отключает |
| `derivativeFilterTime` | 0.02 | Фильтр производной; 0 отключает |
| `maxOutput` | 0.8 | Максимальный модуль нормированного ШИМ, (0; 1] |
| `positionTolerance` | 0.05 | Допуск позиции, не менее одного отсчёта |
| `velocityTolerance` | 0.1 | Допуск скорости для завершения и старта |
| `positionHysteresis` | 0.05 | Дополнительный порог выхода из `inPosition` |
| `settleTimeUs` | 100000 | Время устойчивого попадания в допуски |
| `controlPeriodUs`, `maxTickGapUs` | 5000, 50000 | Период контура и максимальный интервал обновления |
| `softLimitsEnabled`, `softMin`, `softMax` | true, 0, 100 | Машинные программные границы |
| `limitReleaseUs` | 2000 | Подтверждение освобождения MIN/MAX |
| `allowUnhomedRelative` | true | Разрешение относительных команд до homing |
| `unhomedMaxDistance`, `unhomedMaxSpeed` | 10, 2 | Пределы относительной команды до homing |
| `recoveryMaxDistance`, `recoveryMaxSpeed` | 10, 1 | Пределы отхода от концевика |
| `maxFollowingError`, `followingErrorTimeUs` | 5, 100000 | Ошибка слежения и допустимое время; порог 0 отключает проверку |
| `stallOutput`, `stallVelocity`, `stallTimeUs` | 0.6, 0.02, 500000 | Признаки возможного заклинивания; `stallOutput = 0` отключает |
| `maxEncoderRate` | 0 | Предел приращения счётчика, отсчётов/с; 0 отключает |
| `endAction`, `faultAction` | HOLD, COAST | Действия после завершения и при аварии |

`stallOutput` не должен превышать `maxOutput`; при уменьшении мощности уменьшите и этот порог либо отключите проверку. Скорости homing не должны превышать `maxSpeed`.

| Поле `home` | По умолчанию | Назначение |
|---|---:|---|
| `source`, `direction` | SEPARATE, −1 | Источник и направление поиска |
| `searchSpeed`, `latchSpeed` | 2, 0.5 | Быстрый и повторный медленный подход |
| `backoff` | 1 | Минимальный отход после первого поиска |
| `switchPosition`, `parkPosition` | −1, 0 | Координата фронта датчика и парковки |
| `debounceUs` | 2000 | Подтверждение состояния Home |
| `timeoutUs` | 30000000 | Ограничение времени всей процедуры |
| `maxTravel` | 1000 | Ограничение суммарного пути всей процедуры |

`begin()` проверяет конфигурацию до её применения. Повторный успешный `begin()` сбрасывает привязку, рабочее смещение и состояние контроллера; во время движения возвращается `BUSY`. Изменение масштаба выполняйте через отключение и новый `begin()`.

`setMaxSpeed()`, `setAcceleration()`, `setDeceleration()` доступны в покое **с отключённым удержанием**: сначала `disable()`. Скорость отдельного движения передаётся вторым аргументом `moveTo()`/`moveBy()` и не меняет конфигурацию. Нулевой аргумент скорости выбирает настроенный предел. Отрицательная скорость перемещения к точке недопустима; направление определяется целью. Для `jog()` знак скорости задаёт направление.

## Ошибки и восстановление

Ошибки фиксируются: устранение причины само по себе не возобновляет движение. `clearFault()` требует исправного входа энкодера, неактивного аварийного входа, освобождённых MIN/MAX и малой измеренной скорости. После сброса выход остаётся отключённым, прежняя команда не запускается. Для освобождения ещё нажатого одиночного концевика используйте явный `recoverFromLimit()`.

| Ошибка | Причина |
|---|---|
| `EMERGENCY_STOP` | Аварийный вход или вызов `emergencyStop()` |
| `MIN_LIMIT`, `MAX_LIMIT`, `BOTH_LIMITS` | Физические ограничения |
| `SOFT_LIMIT` | Фактическая позиция вне программного диапазона с учётом допуска |
| `ENCODER_INVALID` | `Inputs.encoderValid == false` или переполнение накопителя |
| `ENCODER_RATE` | Приращение превышает `maxEncoderRate × dt + 2` отсчёта |
| `CONTROL_TIMEOUT` | Интервал обновления превысил предел во время движения или удержания |
| `FOLLOWING_ERROR` | Позиция отстаёт от текущего профиля больше порога заданное время |
| `STALL` | Значительный выход и ненулевая требуемая скорость при малой измеренной скорости заданное время |
| `HOMING_TIMEOUT`, `HOMING_TRAVEL` | Превышен лимит процедуры homing |
| `NUMERIC_ERROR` | Нечисловое или бесконечное значение в вычислениях регулятора |

Ошибки измерения, времени управления, аварийного останова и числовая ошибка сбрасывают привязку. Любая авария во время homing также её сбрасывает. Обычный концевик, ошибка слежения или stall вне homing сохраняют привязку при условии достоверного счётчика.

Проверки слежения и stall используют временные выдержки. Они помогают обнаружить проблему, но не определяют её причину однозначно. Обрыв A/B, когда счётчик просто перестал меняться, невозможно достоверно отличить от неподвижной механики только по этому счётчику. Подключите диагностику датчика/драйвера через `Inputs.encoderValid`, если она доступна.

## API

Все команды возвращают `axis::Result`, кроме немедленных `disable()`, `brake()`, `emergencyStop()`, `invalidateReference()`. Для печати предусмотрены `axis::toString()` для Result, Fault, Mode, Completion.

| Метод | Назначение |
|---|---|
| `attachEncoder(reader, context)` | Атомарное чтение 32-битного счётчика |
| `setPins(pins)` | Настройка GPIO входов |
| `attachInputs(reader, context)` | Альтернатива GPIO: чтение логических входов и достоверности энкодера |
| `begin(config)` | Инициализация без запуска движения |
| `tick()` | Опрос и обновление; `true`, если выполнен шаг управления или обработана авария |
| `home()` | Запуск привязки |
| `moveTo(position, speed = 0, frame = MACHINE)` | Абсолютная цель |
| `moveBy(distance, speed = 0)` | Перемещение от фактической позиции на момент принятия |
| `moveToAngle(angle, direction = SHORTEST, speed = 0)` | Цель по модулю периода |
| `jog(signedVelocity)` | Непрерывное движение; остановка через `stop()` |
| `recoverFromLimit(direction, distance, speed = 0)` | Ограниченный отход от MIN/MAX |
| `setWorkPosition(position)` | Назначение рабочей координаты текущей точке |
| `setMotorReverse(bool)` | Инверсия выхода; останавливает удержание и сбрасывает привязку |
| `setDeadtime(uint8_t us)` | Настройка deadtime GyverMotor2 |
| `setMaxSpeed`, `setAcceleration`, `setDeceleration` | Изменение пределов в отключённом покое |
| `stop`, `disable`, `brake`, `emergencyStop`, `clearFault`, `invalidateReference` | Управление остановкой и восстановлением |

Переподключение энкодера или входов требует нового `begin()`; во время движения оно отклоняется. `attachInputs()` заменяет чтение всех настроенных GPIO, а не дополняет его. Вызов с `nullptr` возвращает чтение GPIO. Callback входов вызывается перед callback энкодера: для внешнего датчика можно обновить общий снимок в callback входов, затем вернуть из второго callback уже сохранённый счётчик.

Геттеры: `isInitialized()`, `isHomed()`, `isBusy()`, `inPosition()`, `getPosition()`, `getWorkPosition()`, `getVelocity()`, `getTarget()`, `getAngle()`, `getCounts()`, `getDuty()`, `getFault()`, `getMode()`, `getHomePhase()`, `getCompletion()`, `getConfig()`.

`getDuty()` — последнее применённое знаковое задание ШИМ. При торможении оно равно нулю, хотя пины драйвера могут оставаться активными. Полное действие выхода находится в `snapshot().output.action`.

`snapshot()` дополнительно содержит заданные профильные координаты и скорость, команду скоростного контура, ошибку слежения, интегратор, признак насыщения, выход и сырые логические входы. Сам Axis ничего не печатает в Serial.

Результаты принятия: `OK`, `NOT_INITIALIZED`, `INVALID_ARGUMENT`, `BUSY`, `NOT_HOMED`, `OUT_OF_RANGE`, `LIMIT_ACTIVE`, `FAULT_ACTIVE`, `UNSUPPORTED`. При нескольких причинах возвращается первая проверенная, например `BUSY` во время движения.

## Время выполнения и ESP32

Вызывайте `tick()` на каждом проходе быстрого `loop()`. Регулятор выполняется по `controlPeriodUs`, используя фактически прошедшее время. Частый вызов не ускоряет профиль. После задержки не выполняется серия устаревших шагов «вдогонку». Переполнение `micros()` учитывается арифметикой `uint32_t`; не допускайте интервалов между вызовами, сравнимых с полным периодом переполнения.

Опрос входов и callbacks выполняется при каждом `tick()`. Они должны иметь ограниченное время выполнения. Блокирующие I2C/SPI-операции, длительная печать, сетевые вызовы и `delay()` могут сорвать контур.

На ESP32 все методы Axis вызывайте из **одной задачи**. Объект не защищён от параллельных команд, `tick()` или чтения `snapshot()` другим ядром. Из ISR вызывается только обновление счётчика энкодера. Сам `tick()` не вызывается из ISR: он выполняет вычисления с плавающей точкой и операции GPIO.

Собственной задачи, таймера или watchdog библиотека не создаёт. `CONTROL_TIMEOUT` обнаруживается при следующем вызове после задержки; пока процессор завис, программа не может переключить выход. Если требуется независимая реакция, используйте аппаратный watchdog/контроль драйвера и аппаратную цепь аварийного останова.

## Настройка на своей механике

1. Проверьте масштаб: вручную переместите механизм на известное расстояние и сравните изменение отсчётов. Уточните PPR/CPR, режим ×4 и передаточное отношение.
2. Проверьте согласование знаков двигателя и энкодера при небольшой мощности и коротком относительном перемещении. При положительном движении координата должна увеличиваться. Ошибочный знак обратной связи может разгонять мотор.
3. Задайте небольшие `maxOutput`, скорость, ускорение и достаточные ограничения ошибок. Если уменьшаете `maxOutput`, согласуйте `stallOutput`.
4. Настраивайте скоростной контур с `velocityKi = 0`, `velocityKd = 0`, затем добавляйте интегральную составляющую для устранения устойчивой ошибки. Проверяйте положительное и отрицательное направления и разные нагрузки. До homing для этого доступны ограниченные относительные перемещения; полноценный `jog()` — после homing.
5. После устойчивой работы скорости настройте `positionKp`. Слишком большой коэффициент может вызвать колебания. Производную скорости добавляйте только при необходимости и с фильтрацией.
6. Настройте homing, убедитесь в повторяемости привязки и освобождении датчика после парковки.
7. Проверьте торможение перед обеими программными границами на разных скоростях. Проверьте каждый концевик, аварийный вход, неподвижный счётчик и задержку `tick()`.

Снимки заданных и измеренных позиции/скорости, ШИМ и насыщения помогают понять, не слишком ли агрессивен профиль. Повышение коэффициентов не устраняет недостаток мощности, люфт или недостаточное разрешение энкодера.

Входы ESP32 рассчитаны на уровни своей платы: согласуйте напряжение выхода энкодера. В примерах регистрация прерываний и начальное чтение выполняются в `setup()`.

Линейные примеры принимают `h` — home, `a` — машинная цель 20, `r/l` — ±5, `j` — jog +2, `s` — плавный стоп, `d` — отключение, `c` — сброс ошибки, `+/-` — отход от концевика, `e` — программная авария. AVR-пример также принимает `b` — тормоз, `z` — рабочий ноль, `w` — рабочая цель +5. Настройки Serial: 115200 бод. Отправляйте команды по одной; перевод строки игнорируется.

## Проверка и разработка

Нативные тесты используют реальный заголовок GyverMotor2, зафиксированный на commit `29972794183db1d92df00ef0e71a38dcac48545d`, и тестовый Arduino GPIO-адаптер. Это не подмена реализации GyverMotor2. Модель двигателя проверяет движение и ошибки без оборудования, но не моделирует всю электрическую и механическую динамику реального станка.

```sh
python tests/run_tests.py
```

Для проверки неопределённого поведения используйте `--sanitize`, для сборки с отключённым модулем ускорения зависимости — `--no-motor-accel`. Предупреждения собственного кода в нативной сборке считаются ошибками; заголовок сторонней зависимости подключается как системный.

Нужны Python 3.9+ и `g++`, `clang++` либо Zig в PATH. На Windows без компилятора можно один раз запустить:

```sh
python tests/run_tests.py --download-compiler
```

Скрипт загружает portable Zig 0.13.0 в `.tools/`, проверяет SHA-256 по официальному индексу Zig и хранит кэш/результаты в `.build/`. Первое получение компилятора и зависимости требует доступа к сети. Изменений системной установки компилятора не происходит.

Для сборки примеров установите Arduino CLI и необходимые ядра:

```sh
arduino-cli core update-index
arduino-cli core install arduino:avr@1.8.6
arduino-cli core update-index --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core install esp32:esp32@3.3.2 --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
python tests/compile_examples.py
```

`compile_examples.py` собирает и линкует примеры для Uno, ESP32 и адаптер внешней обратной связи для ESP32-S3. Он **не прошивает** плату. Можно выбрать `--target avr`, `--target esp32`, `--target esp32s3`, задать `--cli` и `--config`. Подробный вывод включается через `--verbose`; `--log путь_к_файлу` сохраняет полный журнал и печатает краткие итоги.

Итоги локальных проверок: [tests/VALIDATION.md](../tests/VALIDATION.md). Workflow [checks.yml](../.github/workflows/checks.yml) задаёт нативные проверки и сборку примеров при push/PR; наличие файла workflow само по себе не означает успешный запуск удалённого CI.

Архив для установки через Arduino IDE создаётся командой `python tools/package.py` в `dist/Axis-0.1.0.zip`. В него не попадают `.build`, `.tools`, `.git` и локальные настройки агента.

При работе напрямую с `axis::Core` передавайте в `begin()` и `tick()` время в микросекундах, сырой счётчик и `Inputs`. Методы ядра не переключают GPIO. После команд с немедленным действием вызывающая обвязка должна применить `getOutput()`. Перед принятием команд обновляйте входной снимок; Arduino-обёртка Axis делает это автоматически.

## Ограничения версии

- Нет испытаний на реальном станке и универсальных коэффициентов регулирования. Проверка компиляции не подтверждает электрическую совместимость или гарантированный тормозной путь.
- Нет шаговых STEP/DIR-приводов, BLDC-коммутации, замкнутого контура тока, управления механическим тормозом или силовым Enable отдельным пином.
- Нет очереди, перепланирования цели на ходу, изменения подачи во время движения, S-профиля, паузы с возобновлением и автоподбора PID.
- Нет автоматического сохранения конфигурации/координат в EEPROM/NVS, компенсации люфта, энкодерного индекса Z и протоколов абсолютных энкодеров.
- Нет встроенного PCNT; аппаратный счётчик подключается callback-функцией.
- Нет общего планировщика нескольких осей, G-code и режима внешней траектории. Независимые `moveTo()` не обеспечивают согласованный контур инструмента. Ядро отделено от драйвера для дальнейшего расширения.
- Один экземпляр управляет одной осью. На малых AVR нужно отдельно проверять Flash, RAM, стек и реальное время выполнения для своего скетча.
