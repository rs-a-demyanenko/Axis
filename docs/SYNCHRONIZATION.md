# Синхронизация Axis

[← Главная](../README.md) · [Руководство одной оси](GUIDE.md)

## Какой режим выбрать

| Задача | Интерфейс | Как формируется движение |
|---|---|---|
| X проходит 1 мм, Y — 2 мм | `AxisGroup<2>` | Один общий S-профиль с учётом пределов всех осей |
| Z проходит 1 мм за оборот управляемой A | `AxisGear` + `AxisMaster` | Ведомая следует заданному или измеренному положению A |
| Z следует углу внешнего шпинделя | `AxisGear`, `STRICT` + `EncoderMaster` | Жёсткая связь целевой позиции с отсчётами энкодера |
| Подача по оборотам с плавным разгоном Z | `AxisGear`, `LIMITED` + `EncoderMaster` | Отдельное ограничение скорости, ускорения и рывка с диагностикой отставания |

ПИД-контуры позиции и скорости работают во всех режимах. При внешнем задании отключается только собственный планировщик перемещения ведомой. Концевики, программные границы, ограничения выхода, ошибка слежения, stall и контроль времени остаются активными.

Точное соотношение относится к **заданиям координат**. Фактическая точность зависит от энкодеров, механики и настройки сервоконтуров; отклонение нужно контролировать по диагностике. Программное обновление выходов одного цикла не является аппаратным одновременным переключением всех GPIO.

## Общий профиль X/Y

Оси должны быть инициализированы и успешно выполнить Home. Подключать группу можно заранее, но запуск движения требует неподвижных осей и отсутствия аварий.

```cpp
Axis<GM2::DIR_PWM> x(26, 25), y(14, 27);
AxisGroup<2> xy;

// После настройки пинов, энкодеров и begin() обеих осей:
xy.add(x.syncPort(), 1);
xy.add(y.syncPort(), 2);
xy.setPhaseLimit(0.2, 100000);  // Дополнительный контроль контура, в единицах X.

// По команде оператора после Home:
xy.moveBy(10, 5);              // X +10 мм, Y +20 мм; запрос скорости до 5 X-мм/с.

// На каждом проходе loop():
xy.tick();
```

Значения коэффициентов задают приращения от начальных положений движения:

```text
p_i = p_i_start + ratio_i × s
v_i = ratio_i × v_s
a_i = ratio_i × a_s
j_i = ratio_i × j_s
```

`s` — общая координата профиля. Для X:Y = 1:2 `ratio_X = 1`, `ratio_Y = 2`. Отрицательный коэффициент меняет направление. Нулевой коэффициент удерживает участника на начальной позиции; у первой оси он должен быть ненулевым. Один объект Axis нельзя добавить дважды.

Общие пределы выбираются по самой ограничивающей оси:

```text
v_s_max = min(maxSpeed_i / abs(ratio_i))
a_s_max = min(acceleration_i / abs(ratio_i))
d_s_max = min(deceleration_i / abs(ratio_i))
j_s_max = min(maxJerk_i / abs(ratio_i))   // только положительные maxJerk
```

Например, X допускает 10 мм/с, Y — 15 мм/с. При отношении 1:2 общая скорость ограничена 7,5 X-мм/с: Y движется со скоростью 15 мм/с. Если запросить больше, замедлится весь общий профиль. Аналогично пересчитываются ускорение и рывок. Ось с `maxJerk = 0` не ограничивает общий рывок; если так настроены все участники, группа использует конечный S-рывок `10 × a_s_max`.

`moveTo(position, speed)` задаёт абсолютную **машинную** позицию первой оси; остальные перемещаются пропорционально. При первом коэффициенте 1 и отношении 1:2 переход X=5 → X=8 перемещает Y на +6 относительно её текущей точки. Новые начальные положения фиксируются при каждой команде.

`setRatio(member, ratio)` позволяет менять коэффициент зарегистрированного участника между движениями. Во время активной группы он возвращает `BUSY`; новая команда заново пересчитывает общие пределы.

Все конечные точки проверяются до запуска. Цель вне программной границы отклоняется с `OUT_OF_RANGE`; движение не начинается частично. `isBusy()`/`isActive()` остаются истинными до окончания профиля и попадания **всех** осей в их позиционные и скоростные допуски на требуемое время.

### Остановка и ошибки группы

- `xy.stop()` во время общего движения строит одно S-торможение и сохраняет соотношения заданий. В покое группы он также останавливает независимые движения её участников, например Home.
- `xy.disable()` сразу отключает выходы всех участников.
- `xy.emergencyStop()` фиксирует аварийный останов у всех участников.
- Концевик, авария, потеря обратной связи или несвоевременный цикл одной оси прерывают всю активную группу. Выходы сначала вычисляются, затем применяются: авария более позднего участника не допускает частичной записи нового движения остальным.
- `xy.getError()` возвращает `SyncError`, а `axis.getFault()` сохраняет первичную ошибку конкретной оси. У остальных появляется `SYNC_FAULT`.
- `xy.clearFault()` требует устранения причин и неподвижных осей. Старое движение автоматически не возобновляется.

### Контур и период управления

Общий период — максимум `controlPeriodUs` всех участников. Все ПИД-контуры группы обновляются на этих общих границах времени. `maxTickGapUs` каждой оси должен допускать такой период с запасом на реальные задержки. Опрос энкодеров и входов продолжается при промежуточных вызовах `xy.tick()`, поэтому физические аварийные входы не ждут общего шага регуляторов.

Настройте фильтр скорости и коэффициенты под **общий** период. Слишком малое время фильтра при редких отсчётах может вызвать дрожание и не позволить выполнить условие устойчивой остановки.

Обычный контроль слежения каждой оси активен всегда согласно её конфигурации. Дополнительный `setPhaseLimit(error, timeoutUs)` контролирует рассогласование фактического движения участников, нормированное в единицы общей координаты `s`. По умолчанию этот дополнительный порог равен 0 и отключён; для точного контура настройте его явно с учётом разрешения энкодеров.

`xy.phaseError(i)` возвращает ошибку участника в его **собственных** физических единицах относительно фактического движения первой оси. Для X:Y = 1:2 это `ΔY − 2 × ΔX`. При проверке общего порога ошибка делится на коэффициент участника. Нулевой коэффициент обслуживается обычным контролем удержания, без деления на ноль.

Полные примеры: [ESP32](../examples/SynchronizedXY_ESP32/SynchronizedXY_ESP32.ino), [Mega 2560](../examples/SynchronizedXY_Mega/SynchronizedXY_Mega.ino).

## Управляемая ведущая ось A и ведомая Z

`AxisMaster` получает состояние уже работающего Axis:

```cpp
axis::AxisMaster master(axis::MasterFeedback::MEASURED);
AxisGear az;

// В loop(), сначала обновляем ведущую:
a.tick();
const axis::MasterSample& sample = master.update(a.controlCore());
if (az.isActive()) az.tick(sample);
else z.tick();
```

В покое, после Home обеих осей, связь включается отдельной командой:

```cpp
axis::GearConfig config;
config.ratio = 1.0 / 360.0;          // 1 мм Z за 360 градусов A.
config.mode = axis::GearMode::STRICT;
config.maxPhaseError = 0.2;          // В мм ведомой Z.
az.engage(z.syncPort(), sample, config);

// Затем можно командовать ведущей:
a.moveBy(360, 60);                 // Оборот A → приращение Z на 1 мм.
```

Связь фиксирует текущие начала координат и использует `z_ref = z_start + ratio × (a − a_start)`. Коэффициент задаётся в **единицах ведомой на единицу ведущей**. Вращательный Axis использует градусы, поэтому 1 мм/оборот соответствует `1/360`, а не 1.

`MasterFeedback::MEASURED` следует фактическому положению энкодера; скорость берётся из Axis, ускорение и рывок оцениваются с фильтрацией. `REFERENCE` берёт рассчитанные ведущей позицию, скорость, ускорение и рывок; этот вариант позволяет следовать её траектории без энкодерной квантованности в задании. Для согласованного ограничения возможностей обеих управляемых осей используйте `AxisGroup` — одиночная электронная передача не меняет настройки ведущей автоматически.

При ошибке ведомой ведущую можно остановить обработчиком:

```cpp
void stopMaster(axis::SyncError, void*) { a.emergencyStop(); }
az.setFaultHandler(stopMaster);
```

Чтобы замедлить A и сохранить связь Z, вызовите `a.stop()` и продолжайте обновлять передачу. `az.stop()` **отключает связь**, после чего Z завершает собственное S-торможение; отношение к продолжающей вращаться A больше не сохраняется.

Полный пример: [RotaryGear_ESP32](../examples/RotaryGear_ESP32/RotaryGear_ESP32.ino).

## Внешний шпиндель с энкодером

Шпинделю не требуется объект Axis и драйвер GyverMotor2. `EncoderMaster` принимает атомарно прочитанный инкрементальный счётчик:

```cpp
axis::EncoderMaster spindle;
axis::EncoderMasterConfig encoderConfig;
encoderConfig.countsPerRevolution = 2000;  // После декодирования A/B ×4.
spindle.begin(encoderConfig, micros(), readSpindleCount());

// В loop():
spindle.update(micros(), readSpindleCount());
if (feed.isActive()) feed.tick(spindle.sample());
else z.tick();
```

Этот источник выдаёт **накопленные обороты**, а не угол 0…360°. Поэтому коэффициент 1 означает 1 мм ведомой на оборот шпинделя. Знак коэффициента или `encoderConfig.inverted` меняет направление. Выбор нуля начала связи не требует машинного Home шпинделя; ведомая ось Z должна быть привязана.

```cpp
axis::GearConfig config;
config.ratio = 1;                         // 1 мм/оборот.
config.mode = axis::GearMode::LIMITED;     // либо STRICT.
config.maxPhaseError = 2;                 // Допустимое отставание Z, мм.
config.phaseErrorTimeUs = 100000;
config.sourceTimeoutUs = 50000;
feed.engage(z.syncPort(), spindle.sample(), config);
```

Полный пример с A/B, атомарным чтением и обоими режимами: [SpindleSync_ESP32](../examples/SpindleSync_ESP32/SpindleSync_ESP32.ino).

### STRICT — угловая связь

Целевая координата непосредственно связана с углом/отсчётами ведущего. У ведомой нет второго независимого разгона, который изменял бы эту связь. Собственный PID продолжает отслеживать поступающую позицию и скорость.

Пределы скорости, ускорения и рывка ведомой проверяются по состоянию задания. Если их нельзя соблюсти, передача фиксирует ошибку, а не молча растягивает шаг. Для шумных энкодеров настройте фильтры и диагностические пределы. Ошибка фактического следования также контролируется.

В этой версии `STRICT` включается **в покое ведущего и ведомой**. Нужен хотя бы один измеренный кинематический снимок: `EncoderMaster.sample().ready` становится истинным после первого шага измерения. Это предотвращает принятие начальной нулевой скорости источника за доказательство остановки. Подключение на вращении возвращает `BUSY`.

Угловая связь является основой подачи постоянного шага. Готовый многопроходный резьбонарезной цикл потребует также индекса Z и повторяемого фазового входа; эти функции пока не реализованы. Например, [LinuxCNC G33](https://linuxcnc.org/docs/html/gcode/g-code.html#gcode:g33) использует индекс шпинделя для совмещения проходов. Не считайте `STRICT` готовой заменой всего цикла G33.

### LIMITED — плавная подача с сохранением ограничений

Связь можно включить при вращающемся шпинделе. Сначала рассчитывается идеальная позиция из накопленных оборотов. Затем отдельный генератор формирует достижимое задание с ограничениями скорости, ускорения и рывка Z. Скоростной PID и обратная связь по позиции работают поверх него.

Во время разгона или резкого изменения шпинделя ведомая может отставать. Это неизбежно, если требуемое ускорение ведущего через коэффициент превышает возможности ведомой: из `z = k × theta` следует `a_z = k × a_theta`. Нельзя одновременно сохранить жёсткую фазу и независимо уменьшить ускорение Z при произвольном изменении шпинделя.

Пройденные обороты не теряются: идеальная цель продолжает накапливаться, а Z догоняет её в пределах своих возможностей. После остановки шпинделя идеальная конечная позиция сохраняется. Коэффициент `captureGain` определяет добавку скорости для устранения отставания; слишком агрессивная настройка может вызвать колебания. Для догоняния на ходу нужен запас скорости выше установившейся подачи.

`maxPhaseError` и `phaseErrorTimeUs` ограничивают допустимое рассогласование. Превышение фиксирует `PHASE_ERROR` и останавливает ведомую. Этот режим подходит для плавной подачи по оборотам с допустимым переходным отставанием; он не гарантирует постоянный шаг резьбы во время разгона.

Если `maxJerk > 0`, генератор использует S-переходы с перепланированием из текущих скорости и ускорения. Ускорение ограничивается минимумом `acceleration` и `deceleration`, чтобы безопасно менять направление. При `maxJerk = 0` сохраняется ограничение ускорения с прежними скачками ускорения. Идеальная цель за программной границей вызывает ошибку; источник шпинделя библиотека сама не останавливает.

## Диагностика передачи

```cpp
axis::GearSnapshot status = feed.snapshot();
```

| Поле | Значение |
|---|---|
| `active` | Передача подключена |
| `inSync` | Фактическое положение, отставание задания и скорость находятся в допусках ведомой |
| `idealPosition` | Позиция, требуемая точным отношением к ведущему |
| `phaseError` | Идеальная позиция минус фактическая позиция ведомой |
| `referenceLag` | Идеальная позиция минус ограниченная позиция задания |
| `reference` | Выданные ведомой позиция, скорость, ускорение и рывок |
| `error` | Зафиксированный `SyncError` |

`inSync` оценивается при обновлениях контура, а не устанавливается автоматически при вызове `engage()`. Для контроля технологического процесса используйте его вместе с исправностью оборудования и подходящими допусками.

| `SyncError` | Причина |
|---|---|
| `AXIS_FAULT` | Авария оси, включая концевики, энкодер и период управления |
| `SOURCE_INVALID` | Источник отметил данные недостоверными |
| `SOURCE_TIMEOUT` | Не обновлялась временная метка источника |
| `SOURCE_CHANGED` | Сменился источник, его эпоха, масштаб или представление счётчика |
| `REFERENCE_LIMIT` | Требуемая траектория не укладывается в пределы ведомой |
| `PHASE_ERROR` | Рассогласование превышает заданный порог дольше допустимого |
| `INTERRUPTED` | Участник вышел из режима синхронизации внешней командой |
| `NUMERIC_ERROR` | Некорректные вычисления или непредставимое задание |

У оси фиксируется `SYNC_FAULT` либо сохраняется её более ранняя конкретная ошибка. Сброс не возобновляет старую связь: после устранения причины вызовите `clearFault()`, при необходимости повторите Home, затем явно включите передачу. Новый вызов `engage()` фиксирует новые начала отсчёта.

Для внешнего шпинделя подключите `setFaultHandler(handler, context)` к своему интерфейсу остановки. Обработчик вызывается один раз на событие ошибки, после применения безопасного выхода ведомой. В примере устанавливается флаг запроса остановки: сам силовой интерфейс шпинделя должен реализовать код станка. Обработчик должен быть коротким и неблокирующим.

## Достоверность источника

`EncoderMasterConfig` задаёт `countsPerRevolution`, `inverted`, `periodUs` (по умолчанию 5000), `maxGapUs` (50000), `filterTime` (0.02 с) и необязательный `maxCountRate` в отсчётах/с. Счётчик A/B — 32-битный с модульным переполнением; накопление выполняется в `int64_t`. При наличии отсчётов разность для передачи вычисляется целочисленно относительно момента подключения, что сохраняет отдельные импульсы даже при большом общем счёте.

`update(now, raw, encoderValid)` принимает логическую исправность датчика. Потеря исправности, превышение частоты отсчётов или слишком большой разрыв измерений фиксируют недостоверность до нового `begin()`. Повторный `begin()` меняет эпоху источника, поэтому активная связь не продолжится незаметно после сброса счётчика.

Постоянный счёт при регулярно обновляющихся исправных данных означает остановленный шпиндель. По одному неизменному счётчику нельзя отличить остановку от обрыва датчика; при наличии аппаратной диагностики передавайте её через `encoderValid`. Прекращение вызовов обновления обнаруживается по временной метке.

## Порядок вызовов и ресурсы

- Все методы выполняются из одной задачи. Энкодеры читаются атомарно; синхронизация не вызывается из ISR.
- Группа сама обновляет зарегистрированные Axis через `syncPort()`. Пока группа активна, отдельные `axis.tick()`, `axis.stop()` и новые команды оси не используются: обычный tick ведомой без внешнего задания вызывает защитную ошибку, а команды возвращают `BUSY`.
- Передача обновляет только ведомую. Сначала обновите ведущую/энкодер и его снимок, затем вызовите `gear.tick(sample)`. После отключения связи продолжайте `axis.tick()` либо пассивный `gear.tick(sample)`, чтобы закончить локальное торможение и обслуживать удержание.
- Временные метки должны происходить из одного `micros()` с арифметикой `uint32_t`. Опрос источника должен быть достаточно частым для периода контура; фильтрация и задержки измерения влияют на точность фазы.
- Объекты Axis и источников должны жить дольше подключённых координаторов. Координаторы и источники нельзя копировать. При подключении отклоняются ведущая-ведомая на одном Axis и передача от оси, уже находящейся в синхронном режиме; переход ведущей в чужой координатор также прерывает связь. Произвольные цепочки и циклы этой версией не обслуживаются.
- Динамического выделения памяти нет. Вместимость `AxisGroup<N>` задаётся при компиляции. Синхронизация подключается отдельным кодом и не добавляет объектов контроллера к обычному Axis.
- Для нескольких полных осей и шпиндельной логики используйте плату с подходящими Flash/RAM. В комплекте есть пример AVR для Mega 2560; одновременная работа нескольких осей на Uno/Nano не подтверждена и не обещается по одному признаку совместимости Arduino.

Низкоуровневые `axis::Group<N>` и `axis::Gear` принимают явное время в `moveByAt()`, `moveToAt()`, `engageAt()`, `tickAt()` и `clearFaultAt()`. `Core::tickSynchronized()` принимает `ExternalReference`; его PID и защиты остаются активны. Эти интерфейсы позволяют тестировать координацию без Arduino. Обычным скетчам достаточно `AxisGroup`, `AxisGear`, `AxisMaster` и `EncoderMaster`.
