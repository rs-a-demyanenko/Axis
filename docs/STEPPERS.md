# Шаговые двигатели

[← Главная](../README.md) · [Общий API](GUIDE.md) · [Синхронизация](SYNCHRONIZATION.md)

`AxisStepper` защищённо наследуется от `Stepper` из [StepperCore.h](https://github.com/GyverLibs/GyverStepper/blob/main/src/StepperCore.h). От GyverStepper используются отдельный шаг и управление питанием. Планировщик, координаты, P-регулятор позиции, homing, концевики и синхронизация принадлежат Axis. Прямые `step()`, `dir` и `pos` скрыты, чтобы не обходить учёт положения и защиты.

## Подключение

Установите GyverStepper 2.7.2 или совместимую версию. Для нового типа нужен заголовок `AxisStepper.h`; существующий `Axis.h` сохраняет DC-интерфейс.

```cpp
#include <AxisStepper.h>

AxisStepper<STEPPER2WIRE> x(5, 6, 7);                 // STEP, DIR, EN
AxisStepper<STEPPER4WIRE> y(2, 3, 4, 5, 6);           // Фазы 1..4, EN
AxisStepper<STEPPER4WIRE_HALF> z(2, 3, 4, 5);         // Полушаг, без EN
AxisStepper<STEPPER2WIRE, STEPPER_VIRTUAL> external;  // Обработчики драйвера
```

Выберите один нужный объект. EN необязателен; без подключённого EN отключение STEP/DIR прекращает импульсы, но питание драйвера физически не снимается. По умолчанию EN активен низким уровнем; `setEnableInverted(true)` меняет его на высокий. `setMotorReverse(true)` меняет физическое направление при сохранении знака логических координат. Положительное движение должно увеличивать измеренную координату; при обратном знаке энкодера задайте `config.encoder.inverted = true`.

Для виртуального интерфейса до `begin()` обязателен `attachStep(void (*)(uint8_t))`. У STEP/DIR обработчик получает направление каждого отдельного шага; у четырёхфазного драйвера — битовую маску фаз. Необязательный `attachPower(void (*)(bool))` управляет питанием. Эти обработчики выполняются синхронно и должны завершаться быстро; GPIO, длину импульса и время установки DIR в виртуальном режиме обеспечивает приложение.

## Масштаб и выбор обратной связи

```cpp
void setup() {
    x.setStepsPerUnit(640);  // 200 шагов/оборот * 16 микрошагов / 5 мм хода
    axis::Config config;
    config.maxSpeed = 2;     // мм/с, то есть до 1280 импульсов/с
    config.home.searchSpeed = 1;
    config.home.latchSpeed = 0.2;
    x.begin(config);
}
void loop() { x.tick(); }
```

Без `attachEncoder()` ядро получает знаковый счётчик реально выполненных вызовов шага. `begin()` автоматически задаёт `config.encoder.countsPerUnit = stepsPerUnit` и сбрасывает инверсию измерения. При старте позиция условно нулевая; для машинного нуля нужен Home. Привязка и ограниченные перемещения до неё работают так же, как у DC-оси.

С энкодером вызовите `attachEncoder(reader, context)` до `begin()` и отдельно задайте `config.encoder`, например `axis::EncoderScale::rotary(2000, 5)` для 2000 отсчётов на 5 мм. Разрешение энкодера не обязано совпадать с числом шагов. Координаты, скорость, homing и ошибка слежения вычисляются по энкодеру, а частота шагов — по заданию скорости и `stepsPerUnit`. P-регулятор позиции корректирует отклонение от профиля. Скоростной PID коллекторного двигателя и его диагностика `STALL` по ШИМ в этом режиме не используются.

`hasEncoder()` сообщает текущий режим. `detachEncoder()` возвращает подсчёт по шагам. Изменение источника обратной связи и `setStepsPerUnit()` разрешены только вне движения, отключают привод и требуют повторного `begin()`; машинную привязку после этого нужно выполнить заново. Значение масштаба по умолчанию — 100 шагов на единицу. Для вращательной оси единица — градус: например, `200 * 16 / 360.0` шагов на градус.

`positionTolerance` должна быть не меньше одного отсчёта выбранного источника обратной связи. С энкодером также учитывайте размер одного моторного шага и люфт механики. В режиме удержания импульсы коррекции прекращаются внутри допуска, что предотвращает колебание на один шаг.

## Координаты и команды

Общий API описан в [руководстве](GUIDE.md): `moveTo`, `moveBy`, `moveToAngle`, `jog`, `stop`, `home`, `recoverFromLimit`, рабочий ноль, снимки состояния и настройка профиля доступны обоим типам двигателя. `positionKp` действует и на шаговый двигатель. `velocityKp/Ki/Kd`, веса скоростного PID, `velocityFeedforward` и нормированный ШИМ не управляют частотой шагов; в `snapshot().output.velocity` находится команда в физических единицах в секунду. `getDuty()` и `setDeadtime()` относятся только к DC-адаптеру.

`getCounts()`, `getAbsolutePositionCounts()` и `getRelativePositionCounts()` возвращают отсчёты активного источника: шаги без энкодера, отсчёты энкодера с ним. Ядро накапливает их в `int64_t`. `getStepCount()` в обоих режимах возвращает отдельный логический счётчик выданных шагов `uint32_t` с переполнением по модулю 2³². Он не обнуляется при Home, смене рабочего нуля или повторном `begin()`.

`EndAction::HOLD` сохраняет питание и коррекцию положения; `COAST` отключает привод. `brake()` и `FaultAction::BRAKE` останавливают выдачу шагов и оставляют питание для удержания. Для планового торможения с ограничением ускорения и рывка вызывайте `stop()`.

## Обслуживание и ограничения

Вызывайте `tick()` из одного основного потока значительно чаще, чем требуемая частота шагов: `maxSpeed * stepsPerUnit`. `controlPeriodUs` задаёт период расчёта профиля и регулятора; выдача отдельных шагов обслуживается при каждом вызове. Например, для 1280 импульсов/с интервал шага около 781 мкс; период опроса должен быть существенно меньше. Блокирующий Serial, длительное чтение датчиков и другие задержки уменьшают достижимую скорость.

Один вызов выдаёт максимум один шаг. Просроченные импульсы не выдаются пачкой и не добавляются к координате. При недостаточной частоте обслуживания движение отстанет от профиля; ошибка слежения может остановить ось. Ограничение конфигурации в 1 млн шагов/с — только числовой предел, достижимая частота зависит от платы, приложения и длительности импульса. В физическом STEP/DIR режиме `StepperCore` использует короткие задержки `DRIVER_STEP_TIME` для STEP и смены DIR; по умолчанию это 4 мкс. Настройте это определение до подключения заголовка, если драйвер требует другую длительность.

Без энкодера координата показывает командное перемещение. Пропуск шага, проскальзывание и внешнее перемещение вала не обнаруживаются. Home и концевики остаются доступными. С энкодером рассогласование положения обнаруживается через `maxFollowingError` при позиционном движении, удержании и синхронизации. При `jog()` скоростной диагностики заклинивания шаговика нет.

`syncPort()` совместим с `AxisGroup`, `AxisGear`, `AxisMaster` и `EncoderMaster`; группа может содержать DC- и шаговые оси. При работе через координатор часто вызывайте его `tick()` — именно он обслуживает шаги. Самостоятельный `tick()` активной синхронной ведомой вызывает прежнюю защиту `SYNC_FAULT`. Синхронизация относится к общему профилю; одновременность фронтов нескольких STEP аппаратно не гарантируется.

Примеры: [без энкодера](../examples/Stepper_OpenLoop/Stepper_OpenLoop.ino), [с энкодером](../examples/Stepper_Encoder/Stepper_Encoder.ino). Распиновку проверьте по своей плате; успешная компиляция не подтверждает движение на оборудовании.
